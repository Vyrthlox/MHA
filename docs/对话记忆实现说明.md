# AI 对话（记忆 + 真实回复）实现说明

本文档记录 AI 对话功能的完整实现：会话与消息的 MongoDB 持久化、Spring AI 的对话记忆、
调用大模型生成回复的接口，以及前端对话页 `ai-vue/src/views/home.vue` 的接入。

## 1. 范围

已完成：

- 会话（`chat_sessions`）与消息（`chat_messages`）的 MongoDB 持久化
- 基于 Spring AI `ChatMemory` 的对话记忆窗口（8 轮 / 16 条）
- 会话的新建、分页列表、消息历史、删除接口
- 会话归属校验（普通用户只能访问自己的会话，管理员可查看全部）
- 首条用户消息自动生成会话标题、最后一条消息生成列表预览
- `POST /sessions/{id}/messages`：调用大模型生成回复，并同步写入记忆
- 系统提示词 `prompt/sys_chat.md` 的加载
- 前端对话页接入真实接口：会话列表、历史消息、新建、删除、发送与等待状态

暂未实现：

- 流式输出（SSE / WebSocket），当前是同步接口，等整段回复生成后一次性返回

长期记忆、跨会话画像和向量检索已经落地，见
[`docs/上下文工程实现说明.md`](上下文工程实现说明.md)。本文档只描述短期记忆与消息持久化。

## 2. 为什么自己实现 `ChatMemory`，而不是 `ChatMemoryRepository`

Spring AI 自带的 `MessageWindowChatMemory` 在每次 `add` 时，会把**裁剪后的整个窗口**
交给仓储的 `saveAll(conversationId, messages)`。仓储拿到的是「当前窗口」而不是「新增消息」，
无法可靠地区分哪些需要插入：

- 整段覆盖会丢掉窗口之外的完整历史（前端还要回看全部消息）
- 按内容去重无法处理重复文本，也会在窗口滑动时误判

本项目的 MongoDB 是**只追加的完整日志**，所以 `MongoChatMemory` 直接实现 `ChatMemory`：

- `add`：收到什么就追加什么（`MessageChatMemoryAdvisor` 每次只传新消息）
- `get`：从完整历史里取最近 N 条，按时间正序返回给模型
- `clear`：删除该会话的全部消息

已核对 Spring AI 2.0.1 的 `MessageChatMemoryAdvisor` 字节码：请求前 `before()` 调一次
`add` 存用户消息，响应后 `after()` 再调一次存助手回复，因此一条消息只会入账一次。

## 3. 数据模型

### `chat_sessions`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `_id` | String | 会话 id，同时作为 `ChatMemory` 的 `conversationId` |
| `userId` | Long | 归属用户，来自 JWT 的 `sub` |
| `username` | String | 创建时的用户名快照，供管理端展示 |
| `title` | String | 会话标题，默认「新的对话」 |
| `lastMessageContent` | String | 最后一条消息的前 60 个字符 |
| `messageCount` | Integer | 消息条数缓存 |
| `startedAt` | LocalDateTime | 创建时间 |
| `updatedAt` | LocalDateTime | 最近活跃时间，列表按它倒序 |

索引：`{userId: 1, updatedAt: -1}`。

### `chat_messages`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `_id` | String | ObjectId 十六进制 |
| `sessionId` | String | 所属会话 |
| `role` | String | `user` / `assistant` / `system` |
| `content` | String | 消息正文 |
| `createdAt` | LocalDateTime | 写入时间 |

索引：`{sessionId: 1, createdAt: 1}`。

> MongoDB 的日期精度是毫秒。同一毫秒内的消息靠 ObjectId（时间前缀 + 自增计数）
> 作为第二排序键，接口层已统一使用 `createdAt + id` 排序。

## 4. 记忆窗口与系统提示词

```properties
# 16 条 = 8 个来回
# .properties 的行内注释会被当成值的一部分，注释必须单独成行
mha.chat-memory.max-messages=16
# 标题长度
mha.chat-memory.title-max-length=20
# 列表预览长度
mha.chat-memory.preview-max-length=60
```

- 16 条是**消息数**，等于 8 个来回。窗口从 20 调小，是为了给画像、历史记忆和
  当前任务状态留出上下文预算。
- 窗口只影响模型上下文；`chat_messages` 里的完整历史不会因为窗口滑动而删除。
- 系统提示词由 `ChatClientConfig` 在启动时读取 `prompt/sys_chat.md`，通过
  `defaultSystem(...)` 每轮随请求发送，**不写入记忆**，也不会出现在前端消息列表里。
- `pom.xml` 的 `<resources>` 把工程根目录的 `prompt/` 复制到 classpath 的 `prompt/` 下；
  同时保留了一份「工程目录文件」的兜底，未跑资源拷贝时也能启动。

## 5. 接口契约

所有接口都受 `JwtAuthInterceptor` 保护，`/api` 前缀由 `server.servlet.context-path` 提供。

```text
POST /api/psychological-chat/sessions
  200 {"code":200,"msg":"会话创建成功","data":{
        "id":"6ad5...","title":"新的对话","preview":"",
        "sessionTitle":"新的对话","lastMessageContent":"",
        "messageCount":0,"userNickname":"alice",
        "startedAt":"2026-10-19 15:20:05","updatedAt":"2026-10-19 15:20:05"}}

GET /api/psychological-chat/sessions?page=1&size=10
  也接受 currentPage / pageSize（管理端分页组件使用这两个名字）
  mine=true：只返回本人会话（对话页使用；管理员也只看自己的）
  200 {"code":200,"data":{"records":[...],"total":1,"current":1,"size":10}}

GET /api/psychological-chat/sessions/{sessionId}/messages
  200 {"code":200,"data":[
        {"id":"...","role":"user","content":"...","createdAt":"2026-10-19 15:20:05"}]}

POST /api/psychological-chat/sessions/{sessionId}/messages
  body: {"content":"我最近压力很大"}
  200 {"code":200,"msg":"回复成功","data":{
        "sessionId":"...","id":"...","role":"assistant",
        "content":"能感受到你的压力……","createdAt":"2026-10-19 15:20:12",
        "messageCount":2}}

DELETE /api/psychological-chat/sessions/{sessionId}
  200 {"code":200,"msg":"会话已删除","data":null}
  # 会话/消息/工作记忆/待提炼任务立即删除；
  # 该会话产生的 normal 长期记忆进入 30 天保留期，important 记忆与画像保留。
  # 需要立即清空全部记忆时调用下面的 DELETE /memory。

GET /api/psychological-chat/memory?sessionId=可选
  本人画像 + 最近会话的工作记忆（详见上下文工程实现说明）

DELETE /api/psychological-chat/memory
  清空本人长期记忆、画像、工作记忆与待提炼任务

未登录 / token 过期：HTTP 200 + {"code":-1,"msg":"登录已过期，请重新登录"}
非本人会话：{"code":500,"msg":"会话不存在"}（不暴露会话是否存在）
内容为空 / 超长：{"code":500,"msg":"消息内容不能为空"} /
                {"code":500,"msg":"单条消息不能超过 2000 个字符"}
```

会话列表项同时返回 `title/preview` 与 `sessionTitle/lastMessageContent` 两组别名：
对话页用前者，管理端「咨询记录」页用后者。

## 6. 发送流程

```text
前端 POST /sessions/{id}/messages
  → 校验 JWT、会话归属、内容长度
  → 同一会话加锁（固定 64 段的分段锁），避免并发请求读到相同历史
  → PromptContextAssembler 组装画像 / 历史记忆 / 当前任务
  → ChatClient.prompt()
        .system(静态人设 + 动态上下文)
        .user(content)
        .advisors(param(ChatMemory.CONVERSATION_ID, sessionId))
    ├─ advisor.before：读取最近 16 条记忆 + 把本轮用户消息追加到 MongoDB
    ├─ 调用 OpenAI 兼容接口（DeepSeek）
    └─ advisor.after：把助手回复追加到 MongoDB
  → 从 chat_messages 取回刚写入的助手消息（id / 时间）
  → 登记异步记忆提炼任务（90 秒防抖，不阻塞本次响应）
  → 返回 ChatReplyVO
```

几个实现细节：

- **为什么同步**：实现简单，前端拿到完整回复后一次性渲染。代价是长回复时请求会挂很久，
  前端 `sendChatMessage` 单独把超时放宽到 120 秒。
- **谁能发消息**：只允许会话本人。管理员可以查看/删除任意会话（咨询记录页），
  但不能以其他用户的身份继续对话；对话页用 `mine=true` 拉列表，管理员也只看到自己的会话。
- **为什么按会话加锁**：同一会话的两个并发请求会读到相同的历史，模型上下文里会出现
  重复或错序的消息。用固定 64 个锁对象做分段（按 `sessionId.hashCode()` 取模），
  而不是 `Map<sessionId, Lock>`，避免会话删除后锁对象不断累积。
- **失败时的历史**：用户消息在调用模型之前就已写入，所以模型调用失败后这条消息仍会留在
  历史里。前端失败时会重新拉取历史，而不是简单撤回本地气泡。

## 7. 模型配置

密钥全部来自环境变量（不再读取 `tmp/.env`）：

| 变量 | 是否必填 | 说明 |
| --- | --- | --- |
| `API_KEY` | 是 | 模型服务商的 API Key |
| `BASE_URL` | 否 | OpenAI 兼容接口地址，默认 `https://api.openai.com` |
| `MODEL_NAME` | 否 | 模型名，兼容旧名 `MODEL`，默认 `gpt-4o-mini` |

`application.properties` 直接用占位符读取：

```properties
spring.ai.openai.api-key=${API_KEY:${OPENAI_API_KEY:not-configured}}
spring.ai.openai.base-url=${BASE_URL:${OPENAI_BASE_URL:https://api.openai.com}}
spring.ai.openai.chat.options.model=${MODEL_NAME:${MODEL:${OPENAI_MODEL:gpt-4o-mini}}}
```

- 未设置 `API_KEY` 时退回标准 `OPENAI_API_KEY` 或占位值 `not-configured`，
  应用仍能启动（Spring AI 的自动配置在启动时就必须拿到凭证，否则起不来）。
- Windows 用 `setx API_KEY "sk-..."` 等方式写入用户环境变量，**重开终端 / 重启 IDE 后生效**；
  Linux / macOS 写入 shell 配置文件；容器部署时用 `-e` / `env` 注入。

## 10. 本地联调

1. 启动 MongoDB / MySQL / Redis。
2. 后端：先设置 `API_KEY`（以及可选的 `BASE_URL` / `MODEL_NAME`）环境变量，
   再 `cd code/ai-springboot && mvn spring-boot:run`。
3. 前端：`cd ai-vue && npm run dev`，Vite 把 `/api` 代理到 `http://localhost:8080`。
4. 登录后进入对话页：
   - 首次进入自动打开最近一条会话；没有会话时直接输入内容发送，会自动创建会话；
   - 左上角 `+` 新建会话；
   - 右键会话可删除；
   - 发送后显示「正在思考…」，收到回复后自动滚动到底部。

## 11. 后续可以做的事

- **流式输出**：改用 `chatClient.prompt(...).stream().content()` + SSE，首字延迟会明显降低；
  注意流式场景下 advisor 的 `after` 写入时机与前端增量渲染。
- **敏感内容兜底**：系统提示词里已有危机干预流程，但生产环境仍建议增加关键词检测与
  人工/热线转介入口。
- **会话重命名**：目前标题由首条消息自动生成，可增加 `PATCH /sessions/{id}`。
